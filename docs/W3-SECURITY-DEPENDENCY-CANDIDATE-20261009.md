## 2026-10-09 — optional-package metadata preserved after scratch npm resolution

A new real-npm fixture exposed another root issue in the candidate merger: forcing `sharp` as a scratch-only direct dependency removed the `optional: true` flag from the freshly resolved `node_modules/sharp` entry. Transplanting that entry unchanged into the product lock would silently make an optional Next.js native package required in installs that intentionally omit optional dependencies. This is a genuine candidate-source regression, distinct from the public npm registry access blocker.

The scope-locked merger now restores the original lockfile placement flags (`optional`, `dev`, `devOptional`, `inBundle`) for existing security entries and marks newly resolved Sharp native entries optional. The lock verifier rejects drift in those classifications. Real npm CLI fixture checks verify both `npm ci --include=optional` and `npm ci --omit=optional`; the latter must exclude Sharp while retaining the nonoptional source-map-js. This does not relax or replace the unchanged production audit or any GitHub/UAT gate.

**Release state remains BLOCKED**: the public registry-backed lockfile does not yet exist in the candidate and public npm tarball integrity, full actual project npm-ci, HIGH/CRITICAL audit, official complete local gate and exact-commit GitHub UAT have not been verified.
